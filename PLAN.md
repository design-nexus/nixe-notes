# Notes implementation plan

## Current status — 2026-10-21

Phases 1–5 are implemented in release 0.5.5. Phase 2 covers core Markdown/linked-note workflows; Phase 3 adds history, writing presets, graph/collections/canvas, advanced search, and writing projects. Phase 4 adds optional local AI/semantic indexing and suite integrations. Phase 5 adds opt-in personal WebDAV file synchronization, reviewed conflict/deletion handling, binary recovery versions, and a versioned permission-controlled WASM command API. Live Nextcloud/model-server/companion interoperability and production hardening remain distinct validation work; no account or model was available for those checks.

0.5.5 remembers expanded explorer folders per canonical vault, using relative folder paths. Nested expanded/collapsed state survives refreshes and restarts; restoring it preserves lazy folder loading. Refreshes replace directory monitors and ignore results targeting detached trees. The focused GTK check covers nested restoration, independent vault state, preference round-tripping, restart, and collapsed-state retention.

0.5.4 fixes note tab sizing and titles, adds native tab/explorer context menus and note actions in the standard editor menu, and exposes F2 rename/move. Popup descriptions remain copyable without automatic selection; input focus starts with a caret instead of selecting the whole value. Closing now avoids a recursive close request, waits for pending saves, continues after auxiliary windows close, and checks recovery-write success before discarding in-memory work. The targeted GTK check covers readable tabs at 800 px, the actual context-menu rename flow, unselected dialog text, single-request closing with an auxiliary window, cancellation, and save-before-close.

0.5.3 fixes the empty settings viewport and adds populated Appearance, Editor, Vault, Writing, and Integrations groups, including theme selection, folder settings, and history controls. The connected vault now reopens independently of the suite's last-page setting; saved tabs have their own preference. Settings rebuild from current values and resize with the window. A focused GTK check verifies visible controls at 800 px, theme/font persistence, safe folder updates, and reopening the saved vault without setup.

0.5.1 fixes vault onboarding and narrow-window navigation: a native connection popup supports browsing, typed paths, Markdown-file selection, recent vaults, and folder creation; an empty workspace keeps the connection action accessible. Explicit sidebar expansion works below the automatic compact breakpoint. Resolve appears only for actual external conflicts and targets the affected document across tab switches, with stale-comparison protection. The focused GTK regression verifies initial setup/error recovery, Obsidian configuration preservation, expansion at 800 px, and resolving an inactive conflicted note.

This is a feature milestone, not a claim of complete compatibility with every Obsidian feature or plugin. Rendering and architectural limits are recorded below.

## Architecture and dependency decisions

- Independent Rust 2024 workspace, MIT license, binary `nyx-notes`, display name Notes, application ID `io.github.design_nexus.nyx.Notes`.
- Eight crates with real responsibilities: `notes-app` owns shell/UI/preferences and worker coordination; `notes-editor` owns GtkSourceView buffers and native reading presentation; `notes-markdown` derives metadata, source spans, editing patches, and reader blocks; `notes-vault` owns files, recovery, history, knowledge models, and search; `notes-ai` owns the optional provider/vector cache; `notes-glimpse` owns its public SDK plugin; `notes-sync` owns optional WebDAV/state; `notes-plugins` owns optional WASM isolation. No empty future-feature crates.
- GTK4/sourceview5 0.11 match existing Nyx applications. pulldown-cmark 0.13 supplies CommonMark/GFM, wiki/embed events, and source offsets. Saphyr 0.2.2 validates YAML without whole-document serialization. rusqlite 0.40 bundles SQLite/FTS5. GIO supplies monitoring, conditional replacement, desktop trash, and explicit URI/file launching. tempfile supplies synced staging and no-clobber file copies; blake3 identifies versions/cache files; pathdiff derives relative attachment/link paths; rustix supplies Linux no-replace renames.
- Shared `nyx-core` is pinned to `7cd0be5d09cd1d91510794f58bbc720605951c12`; `nyx-ui`/`nyx-theme` to `609c1d2a5af41a8ee3b76ba23611eb30d95a4743`. Cargo.lock is included. No sibling application internals or old monorepo paths are build dependencies. The local STYLE.md is the pinned canonical reference.
- Reuse suite command bar, Inspector, settings card, shortcuts, preferences, typography, and theme engine. Follow Omarchy by default with Tokyo Night fallback. A mandatory libadwaita dependency is unnecessary for these shared controls.
- The GtkSourceView buffer is the only editable document authority. Native reading blocks and live tags are derived; never serialize them back into Markdown. Source/live/reading switches preserve buffer, selection, cursor, and undo history. Hide delimiters away from the active line/selection, rather than replacing source with widgets. Embeds at the cursor use a native live-preview panel.
- Pango labels, native GtkSourceViews, checkbuttons, grids, and pictures render the reading view. Text/URI markup is escaped. Image bytes and note transclusions load through vault workers; recursive transclusion is bounded. Native GtkListViews virtualize reader blocks, outline, and Inspector lists. No embedded browser is used.
- Parser UTF-8 byte ranges map explicitly to GTK character offsets on a worker. Parsing is debounced with revision guards and one in-flight parse per document. GTK live formatting is limited to a viewport window of at most 32,768 source characters. Full affected-block parsing is deferred; source-preserving bounded styling is the current robust model.
- Serialized vault and index workers keep filesystem/database work off GTK. Directory monitors and periodic metadata reconciliation detect changes. Shared settings/theme retain their existing library behavior.
- Saves validate loaded version and digest before GIO conditional replacement. Recovery drafts precede saves. New notes, attachments, and duplicates use exclusive/no-clobber creation. Conflicts stop autosave and offer disk adoption or a separate copy. Recovery never silently replaces disk contents.
- File moves are reviewed plans of exact link-target patches. Journals outside the vault retain before/after note text for conditional resume/restore. Moves never replace an existing destination. Dirty/recovering documents must be saved or resolved before file operations. Canonical path checks prevent vault escape and copying/moving a directory into itself. `.obsidian` is protected.
- Schema 5 caches FTS5 text, aliases, links, tags, properties, headings with source offsets, file fingerprints, and modification timestamps. Old schemas are rebuildable and discarded without touching notes. Search supports quoted phrases, exclusions, nested tags, paths, property predicates, heading results, and saved queries.
- Templates and daily notes produce ordinary Markdown. Attachments remain ordinary files with relative Markdown links. New settings, search caches, recovery drafts, and move journals stay outside the vault; no conversion is required.

## Milestones and acceptance

### 0. Foundation — implemented

Standalone repository, pinned dependencies, style snapshot, architecture boundaries, CI configuration, native packaging, and installer. CI is configured but has not run remotely.

### 1. Working application — implemented

Vault picker/recent vaults, explorer, note/folder creation, tabs, source editor, explicit/automatic save, recovery, external conflict handling, save-copy, find/replace, preferences, typography, writing width, and keyboard shortcuts.

Acceptance: open an existing vault, edit Markdown, and save reliably without conversion. The GTK integration check verifies source bytes, saving, and refusal to overwrite external changes.

Acceptance: native UI check constructs the graph, all collection layouts, history, writing controls, project tools, and a canvas with embedded note/image cards; edits/save preserve JSON extension fields and the open Markdown source. Domain tests exercise the new history, graph, collection edits/conflicts, manuscript compilation, and Canvas format/conflicts. Filesystem/network failure injection and real desktop input/frame profiling remain separate work.

Dependency decisions: reuse [similar](https://docs.rs/similar/3.2.0/similar/) for source-line diffs, [petgraph](https://docs.rs/petgraph/0.8.3/petgraph/) for traversal, and [PangoCairo](https://gtk-rs.org/gtk-rs-core/stable/latest/docs/pangocairo/) for native Unicode text. Follow the [JSON Canvas 1.0 specification](https://jsoncanvas.org/spec/1.0/) with serde flattening for extension attributes. History uses SQLite transactions and content hashes instead of requiring Git or inventing another note storage format. Collection/project/workspace definitions are preferences; the user documents remain Markdown and JSON Canvas files.

### 4. Optional Nyx integrations and AI — implemented

- Optional `notes-ai` crate with a provider abstraction, Assistant-owned local generation/embedding transport, and model-profile-specific SQLite vector caches using sqlite-vec 0.1.9. Chunking, incremental source fingerprints, local background processing, cancellation, clear/force rebuild, related notes, and keyword/vector rank fusion are implemented. The application also builds with AI omitted.
- Native writing assistance covers summaries, rewrites, grammar, expansion/shortening, tone, outlines, and research extraction. Vault answers use bounded retrieved excerpts and source paths. All generated edits remain proposals with visible diff review and stale-revision protection. Semantic related-note/backlink suggestions never edit automatically.
- Public suite control tools expose active-vault search/read/open and reviewed create/append/replace/clipping. Reads and proposed edits have separate opt-in permissions. Asynchronous proposal IDs/status prevent callers from claiming a pending review was already saved. Notes content is explicitly private/untrusted; Assistant policy and its existing first-party Nyx-apps adapter were updated accordingly.
- Pinned Glimpse SDK dependency and a bundled native plugin provide `note QUERY`, new-note actions, append navigation, and heading search through a versioned, read-only local export. The Glimpse host has a narrow validated action adapter; no shell interpretation, network grant, or arbitrary process execution.
- Capture uses its documented public control surface for flattened screenshot/recording attachments and stored OCR. Clipping retains supplied URL/time metadata without automatically fetching a site. Files uses the Markdown MIME/open-file interface. Shared Nyx themes/preferences remain the appearance integration.
- Assistant gained additive model API v1 actions on its existing private correlated socket, reusing the resident model and keeping inference engines/model selection outside Notes. Embeddings default off and require an explicit loopback model server; cloud endpoints/proxies/redirects are refused. Existing news completion/voice commands retain their formats. Assistant and Glimpse updates are installed without restarting them. Source-worktree contracts are coordinated in the umbrella suite manifest without changing published artifact revisions.

Acceptance: local IPC fixtures validate correlation and vectors; deterministic model-free fixtures validate incremental indexing, retrieval, and rebuild behavior; native GTK checks verify permission denial, untrusted reads, cancelled suite proposals, and undoable reviewed generated edits. Pure consumer fixtures cover local-only URLs and safe Glimpse argument handling. Consumer release builds pass; Assistant retains CUDA support. No model downloads or inference were used for verification.

A standalone Browser/Files/Drive API checkout was not available. The documented clipping/MIME interfaces provide stable standalone-safe boundaries rather than importing legacy internals. Real model accuracy, model-server performance, and live Capture/browser sessions remain unmeasured. Existing running processes take installed code on their next normal restart; installation never restarts them. See [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

### 5. Personal sync and extensions — implemented

- Optional `notes-sync` crate separates file transfer/state from GTK. It consumes pinned public `nyx-sync` keyring/retry exports; the shared immutable-journal transport is deliberately not used to serialize Markdown. reqwest 0.12 supplies HTTPS/conditional requests; roxmltree 0.21 supplies bounded namespace-aware DAV XML parsing with DTD disabled. No new Drive/account/cloud-provider infrastructure is invented.
- Native per-vault account/settings, explicit enable, immediate disable/cancellation, background status, retry/backoff, manual sync, relative-path exclusions, safe binary attachments, and dedicated collection creation. Secrets stay in desktop Secret Service; hidden paths, `.obsidian`, and symlinks are excluded.
- SQLite baselines hold digest/ETag versions and durable conflicts/recovery outside the vault. Conditional GET/PUT/DELETE, no-clobber/conditional local publication, exact-content interrupted-commit recovery, and stale-resolution refusal preserve external edits. Both-side changes and all one-sided deletions require native review; keep-local/use-remote/keep-both and explicit deletion labels are supported. Previous binary/text versions can be exported without overwriting a destination; Markdown downloads also enter normal history.
- Optional `notes-plugins` uses MIT/Apache-2.0 wasmi 1.1, import-free WASM modules, fuel/memory/table/module/input/output limits, content-addressed installation, digest-specific permission approval, revocation, native command selection, and a versioned JSON/memory ABI. Processors receive only the confirmed passage and cannot directly edit files. Proposed changes use the shared editable diff reviewer with revision/state/permission checks. The app builds without AI, sync, or extensions.
- [Sync documentation](docs/SYNC.md) records setup, file/transport limits, recovery, and unavailable live-account validation. [Extension API v1](docs/EXTENSIONS.md) documents permissions, ABI, packaging, isolation limits, and a Rust word-count/uppercase example. The initial extension API supports commands/processors; arbitrary panels, persistent plugin state, marketplaces, and Obsidian JavaScript compatibility are excluded.

Acceptance: deterministic sync fixtures exercise first merge, binary attachments, divergent versions, keep-both, both reviewed deletion directions, exclusions, offline failures, interrupted baseline commits, conditional upload races, stale review, and symlink boundaries. A real loopback HTTP fixture covers the WebDAV transport/parser/conditional headers. WASM fixtures cover disabled/missing grants, normal output, package changes, forbidden imports, and fuel exhaustion. The native acceptance check constructs sync settings and extension manager/commands. No live server credentials or third-party extensions are enabled by verification or installation.

## Verification and known limits

Formatting, strict workspace Clippy, domain fixtures, and invisible GTK acceptance checks are the release gates. The release is installed with its binary, launcher entry, and icon; Notes was not opened or restarted.

The original thirteen domain tests cover Markdown spans/Unicode, reader blocks, task/list/property edits, BOM/mixed-newline fidelity, malformed frontmatter, code exclusions, aliases, headings/blocks, backlinks, search filters/rebuilds, templates/daily notes, attachment collisions, file/folder copies, move link patches, partial-operation restoration, external conflicts, symlinks, `.obsidian`, and path boundaries. Two invisible Broadway GTK checks cover modes, selection/undo, large buffers, the integrated vault UI, metadata, links/backlinks, embeds/images, task/property undo, split/rejoin, saving, and conflict drafts. Checks use isolated temporary vaults/XDG directories and fatal GTK criticals. Phase 4 adds model-free IPC/vector/export fixtures. Phase 5 adds three sync/HTTP checks and one WASM isolation check, plus native permission-revocation coverage. Phase 3 checks additionally cover snapshot retention/restoration, graph traversal/filtering, metadata edits with stale-version rejection, ordered manuscript compilation, canvas extension preservation/conflicts, and canvas link updates during moves.

- Parsing still processes full documents on a worker. Measurements of GTK buffer calls are not end-to-end keyboard/IME/frame-latency guarantees; see BENCHMARKS.md.
- Reading is native and deliberately bounded: arbitrary HTML remains literal, math has basic text/Unicode formatting rather than a complete TeX renderer, embedded media opens with native desktop handlers, and third-party Obsidian plugin views/data formats are unsupported. Source remains intact.
- Complex/invalid YAML is preserved; invalid frontmatter cannot be edited through the structured property editor. Templates support documented variables, not arbitrary Obsidian community template scripting.
- Fold support toggles one heading region at a time. Two panes hold independent document tabs rather than two synchronized views of the same note. Unlinked mentions are suggestions, not a complete linguistic entity matcher.
- Hidden entries are omitted from discovery. Symlink directories are not traversed, final symlink notes are read-only, and non-UTF-8 filenames are excluded from text-path indexing. Expanded folder refresh can reset child expansion state.
- Conditional saves depend on local GIO filesystem guarantees. Multi-file moves are journaled rather than one filesystem-wide transaction; external Markdown editors can observe intermediate link updates. An external edit stops resume/restore instead of being overwritten. Power-loss and filesystem fault injection remain future verification work.
- Shared settings/theme libraries still perform their normal small configuration accesses. History is durable state rather than a rebuildable cache; deleting it discards local revisions. Synchronization and third-party execution are optional and disabled until configured. AI and semantic caches are optional; collaboration is excluded.

- Graph layout uses stable folder clusters/phyllotaxis, not a force simulation. Measured 50,000-note graph model construction is 215 ms and depth-two filtering 27 ms; these are not renderer/frame-rate measurements. Graph labels are suppressed at small scales and off-screen nodes are culled.
- Canvas preserves unsupported extension attributes, but does not execute plugin data or render every optional JSON Canvas background/color decoration. Previews are derived native text/images, not arbitrary browser embeds. Geometry/card edits and preview loading are separate; external canvas writes are checked before saving, with a retained draft on conflict.
- History captures versions before writes, including retained save attempts; count/age retention applies when new snapshots are recorded. Source patches preserve line endings and missing final newlines. A revision restore is an editor operation, not an unconditional filesystem rollback.
- Project progress counts whitespace-separated source words after frontmatter. Exports join Markdown; PDF/typesetting and project-specific bibliography tooling are future enhancements.

## Next implementation steps

All five roadmap phases have implementation slices and documented acceptance coverage. Next work is release hardening: validate against a real opt-in Nextcloud account and local model server; measure real desktop typing/IME/graph rendering and long-running sync with realistic vaults; exercise power-loss/filesystem fault cases; and refine any issues found. These are not claims that every Obsidian community plugin, TeX renderer, WebDAV server, or optional extension point is supported.
